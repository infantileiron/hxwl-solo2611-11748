# 烘焙门店冷链交接温度复核

核对到店点温，追查偏热与偏冷的交接批次。

## 业务背景

麦屿烘焙配送组，服务六家门店，三条配送路线分早班与午班送达冷藏馅料。。门店收货员用随车探针记录冷藏馅料的到店点温，配送组每天把交接单合并成 CSV。值班员过去在表格中按班次筛选，再在群里逐个追问越界批次。现在由温控复核汇总分布，将异常读数连同交接单号、门店、批次和探针交给店长与配送巡检员，供复测与巡检排期。

- 平均温度容易掩盖少量偏热交接，也看不出同一天有没有过冷记录。
- 路线与班次分开筛选时，难以确认高尾集中在哪一个组合。
- 群内转发读数经常漏掉批次或探针编号，现场要重复查找交接单。

## 模块

- 值班总览
- 交接明细
- 温控复核
- 温度分布与巡检



## 演示日流程

1. 11 月 16 日 14:10，将 11 月 14–16 日的门店到货记录整理为「麦屿冷藏馅料交接_20261114-16.csv」。
2. 在「交接明细」导入 CSV，确认三条路线、两个班次共 54 条记录，检查交接单号与探针编号。
3. 在「温控复核」设置 2–6 °C 工作区间、1 °C 分箱和 6 条尾部分位样本下限，运行整批读数。
4. 在「温度分布与巡检」核对直方图是否合计 54 条，查看 P05、P50、P95 和各路线的越界计数。
5. 按路线与班次确认南线午班 9 条中有 5 条高于 6 °C，并查看北线早班的两条低温记录。
6. 将筛选改为南线、午班，沿用同一温区重跑，核对 11 月 16 日南线交接 MY-20261116-S-P-03 的 8.1 °C 读数。
7. 按巡检表安排南线卸货口复测和北线冷风口检查，提交复核处置并注明要回填的交接单号。

CSV 示例为 `麦屿冷藏馅料交接_20261114-16.csv`。批次记录保留 SHA-256 指纹，运行记录保存参数、结果和人工复核决定。

## 口径与算法

- 每条交接单以一次到店点温计数。先校验整份明细的交接单号、日期、班次和读数，再按路线与班次取交集。
- 分位用线性插值。读数升序后令 h=(n−1)p，取相邻两项 x[i]、x[i+1]，计算 x[i]+(h−i)(x[i+1]−x[i])，其中 i=⌊h⌋。单条记录的分位等于原读数。
- 标准差按总体口径计算，即 √(Σ(x−均值)²/n)。直方图从 0 °C 对齐分箱，区间左闭右开，保留观测范围内的空箱。
- 可接受温区含上下限。偏冷率、偏热率与越界率均以对应分组的全部有效交接为分母。路线、班次及交叉组按越界率、最远越界幅度和样本数降序排列。
- 分组少于设定样本下限仍展示实测越界与巡检线索，分组分位标记为样本不足。同一 CSV 与参数可得到相同结果，点温用于排查交接，无法还原运输全程温度。

## 启动

需要 Docker 与 Compose v2。在项目目录执行下面的命令。

```sh
cp -n .env.example .env
docker compose config --quiet
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

前端 `http://127.0.0.1:18260`，FastAPI 文档 `http://127.0.0.1:19260/docs`，数据库 `127.0.0.1:17760`。

| 演示角色 | 账号 | 密码 | 权限 |
|---|---|---|---|
| 复核主管 | `admin` | `admin-demo-2611` | 导入、运行、结果复核、审计。含定时分发时可管理计划 |
| 分析员 | `analyst` | `analyst-demo-2611` | 导入、运行、浏览、导出 |
| 只读查看 | `viewer` | `viewer-demo-2611` | 浏览批次、运行和结果，可导出 |

切换账号请先退出。三个账号由确定性示例脚本创建，重复执行会保留现有账号和批次。

## 实现与本地开发

| 位置或服务 | 职责 |
|---|---|
| `frontend/src` | 原生 HTML/CSS/JS 模块，通过 Nginx ` /api/ ` 代理访问后端。改前端文件后执行 `docker compose up -d --build frontend` |
| `backend/src` | Python 3.11、FastAPI、SQLAlchemy。修改算法后执行 `docker compose up -d --build backend worker` |
| `backend/src/domain` | CSV 字段、可控样本、业务分析和参数元数据 |
| `backend/migrations` | 表结构说明 |
| `worker` | 数据库任务领取、Redis 唤醒、计算、CSV 导出 |
| `db` / `redis` | PostgreSQL 16 / Redis 7 |

`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 设定本机端口。`DB_PASSWORD`、`JWT_SECRET` 为运行配置，`SEED_DEMO` 控制启动时生成演示账号和数据。`APP_SUBNET` 设定项目内网，可在地址冲突时调整。共 5 个服务，数据库、Redis 与共享导出使用各自的命名卷。`docker compose down` 停止并保留数据，`docker compose down -v` 同时清除本项目的卷。

前后端共有枚举 `Role`、`Status`、`Review`，分别定义在 `backend/src/constants/enums.py` 和 `frontend/src/constants/enums.js`，用于鉴权、运行状态和复核展示。
